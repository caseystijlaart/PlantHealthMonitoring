== Introduction

Public datasets enable rapid experimentation with machine learning, but their suitability for real-world and constrained applications (e.g., TinyML) varies significantly. 
For this Minor AI for Society project, dataset validation is therefore a critical step to ensure reliable and deployable model performance.

This report evaluates four plant-related datasets to determine their suitability for lightweight machine learning models. 
Each dataset is assessed using a consistent workflow that combines data quality checks with practical model testing, including baseline models, compact neural networks (TinyMLP), regression variants, and anomaly detection.

The goal is to identify which dataset best supports accurate, efficient, and realistic deployment within constrained environments.

== Purpose
This document summarizes the validation work for the four collected datasets and evaluates whether each dataset is suitable for the personal project goals.

The validation focuses on:

* feature availability for the target use case,
* basic data quality checks,
* baseline model behavior,
* compatibility with small models (TinyMLP / TinyRegression), and
* anomaly-detection potential.

== Used Datasets

Kaggle offers a variety of datasets regarding to the given objective.
While many had potential, not all were suitable.
In order to find suitable datasets, it was of great importance to have certain key features be included, such as plant health, soil moisture, temperature and humidity.

The validation in this report uses the following public datasets:

. Indoor Plant Health and Growth Dataset (Kaggle): https://www.kaggle.com/datasets/souvikrana17/indoor-plant-health-and-growth-dataset
. Edge Assisted Agricultural Sensor Dataset (Kaggle): https://www.kaggle.com/datasets/colabsss/edge-assisted-agricultural-sensor-dataset
. Plant Health Biosensor Dataset (Kaggle): https://www.kaggle.com/datasets/programmer3/plant-health-biosensor-dataset
. Plant Health Diseases Dataset (Kaggle): https://www.kaggle.com/datasets/muqaddasejaz/plant-health-diseases-dataset

== Validation Workflow 
The following steps were used for each dataset to keep the validation process consistent and reproducible:

. Imported the raw dataset and inspected schema/column names.
. Checked required fields for the project use case (sensor-like inputs + plant health target).
. Reviewed data quality (missing values, duplicates, data types, and target distribution).
. Performed basic feature preparation and train/test splitting.
. Trained a baseline `RandomForestClassifier` to estimate practical signal strength.
. Trained a compact `TinyMLP` model to evaluate TinyML feasibility.
. Where applicable, trained a compact regression variant (`TinyRegression`) and recorded `MSE`, `MAE`, and `R²`.
. Ran anomaly detection (`IsolationForest`) to evaluate anomaly-detection suitability.
. Compared the outcomes across datasets to rank suitability for deployment constraints.

This workflow was applied to provide both data-quality validation and model-readiness validation before selecting a final dataset.

== Validation Criteria
Each dataset was reviewed using the same checklist:

* Required fields available (light, soil moisture, humidity, ambient temperature, plant health or equivalent target).
* Missing values and duplicates.
* Data types and label format.
* Class balance / target signal quality.
* Baseline Random Forest test performance.
* TinyMLP / TinyRegression feasibility.

== Dataset 1: Indoor Plant Health and Growth Factors

=== Findings

* Baseline performance is low and unstable.
* Adding `Plant_ID` / plant-specific information produces only marginal improvement.
* Correlation analysis indicates weak relationships between input features and the health target.
* Feature importances are relatively flat, suggesting low signal strength.
* Adding extra columns (for example light exposure, soil type, pest presence) did not improve results and in some runs reduced performance.

=== Key Metrics

* Random Forest test accuracy: `0.2140`
* TinyMLP test accuracy: `0.2040`
* Anomaly detections: `132`

== Dataset 4: Plant Health Data

=== Findings

* The dataset is one of the most usable options for the project.
* Raw features show imbalance in predictive power (single-feature dominance).
* After feature engineering, model behavior improves significantly and becomes more suitable for compact models.
* The engineered data set shows a more divided feature importance, rather than being mainly reliable upon one feature as the non-engineered model is.

=== Key Metrics

* Random Forest test accuracy: `0.8240`
* TinyMLP test accuracy: `0.6958`
* TinyRegression: `MSE 0.2840`, `MAE 0.4148`, `R² 0.5388`

=== Engineered Version
As the given dataset appeared to be the most promising, it was decided to do some small data engineering.
The type of data engineering that is used, feature engineering, allows a model to learn better patterns.
Besides that, as the dataset is overly focused on one feature, relationships between features are introduced, interaction features.
This is implemented as in the real world, certain features are connected, but this can not be read from the data, as the model has no idea of the real world relations.

Therefore, the engineered version focuses on finding the relation between different raw values. 
Rather taking the raw data as is, it looks for how can it be used to improve the models feature importance.

== Final Recommendation

For the project objective (small, practical, and deployable predictive models), the Plant Health Data (engineered version) should be used as the primary dataset.
It has the most potential, as from the original dataset validation, it showed promising results.

As back-up or exploratory, the Plant Health Biosensor data should be kept in mind.
While it is not the best suitable for the given objective, it does show some potential, which with further engineer could be brought to light.
