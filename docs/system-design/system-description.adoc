= System Description
The plant health monitoring system is an embedded solution designed to monitor environmental conditions and provide feedback on plant health. 
The system is centered around an ESP32 microcontroller, which collects data from sensors such as soil moisture, temperature, and humidity.

The ESP32 processes this data locally using a lightweight machine learning model to determine the plant’s health status (e.g., healthy, moderate stress, high stress). 
The results are presented to the user through a simple interface, allowing monitoring and basic interaction, such as setting plant-specific preferences.

The system follows a modular architecture consisting of sensors (data collection), the ESP32 (processing), and a user interface (visualization). 
It is designed to operate efficiently on edge hardware with minimal external dependencies, while remaining extensible for future improvements.

== Extensions
The following extensions are categorized using the MoSCoW prioritization method to define which features are essential, desirable, optional, or out of scope for the current version of the plant health monitoring system.

=== Must
These are the core extensions or capabilities required for the system to meet its primary objective.

* The system must monitor key environmental factors relevant to plant health, such as soil moisture, temperature, and humidity.
* The system must process sensor data and provide plant health feedback to the user.
* The system must present the measured values and plant status through a user interface.
* The system must operate on the ESP32 platform as the main embedded controller.
* The system must support a basic warning or alert when plant conditions fall outside acceptable ranges.
* The system should provide clearer interpretation of plant condition, for example by classifying status as healthy, moderate stress, or high stress.

=== Should
These features are important and would significantly improve the system, but the system can still function without them in the first version.

* The system should allow the user to enter plant-specific preferences, such as whether a plant prefers low, medium, or high moisture.
* The system should store historical sensor readings for later review.
* The system could support multiple plants instead of only one monitored plant.

=== Could
These are optional enhancements that may improve usability or functionality if time and resources allow.

* The system could include additional sensors, such as light intensity or air quality sensors.
* The system could provide trend visualization, such as graphs of moisture or temperature over time.
* The system could include personalized recommendations for plant care actions.

=== Won't
These items are intentionally excluded from the current scope of the project.

* The system won’t include full automation of plant care, such as automatic watering, in the current version.
* The system won’t use a complex cloud backend as part of the initial prototype.
* The system won’t support large-scale commercial greenhouse management.
* The system won’t include advanced computer vision or camera-based plant disease detection.
* The system won’t aim to support every plant species with fully customized biological models.
